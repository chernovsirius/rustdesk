# SiriusDesk — сборка с зашитым сервером

## Секреты GitHub

`Settings → Secrets and variables → Actions → New repository secret`:

| Секрет                | Пример                      | Обязателен |
|-----------------------|-----------------------------|------------|
| `SIRIUS_ID_SERVER`    | `desk.it-sirius.ru`         | да         |
| `SIRIUS_API_SERVER`   | `https://desk.it-sirius.ru` | да, если нужна статистика/CRM |
| `SIRIUS_KEY`          | содержимое `id_ed25519.pub` | да         |
| `SIRIUS_RELAY_SERVER` | `desk.it-sirius.ru:21117`   | нет (по умолчанию берётся из ID-сервера) |

Имя приложения — переменная (не секрет) `SIRIUS_APP_NAME` во вкладке
`Variables`, по умолчанию `SRSDesk`. Допустимы только латиница, цифры и дефис
(`SRS_Desk` нельзя: установщик Windows и ссылки `srsdesk://` не принимают `_`).

Сборка: `Actions → Flutter Tag Build → Run workflow` (или пуш тега `vX.Y.Z`).
Значения подставляются при компиляции (`option_env!` в `src/sirius.rs`). Если
`SIRIUS_ID_SERVER` не задан, клиент ведёт себя как обычный RustDesk.

Локальная сборка: те же переменные окружения перед `python3 build.py --flutter`.

## Имя приложения (Windows)

На Windows программа работает как `SRSDesk`: служба, папка установки
`Program Files\SRSDesk`, настройки `%AppData%\SRSDesk`, MSI со своим кодом
обновления. Поэтому её можно ставить рядом с обычным RustDesk — они не мешают
друг другу. На Linux/macOS/Android внутреннее имя пока `RustDesk` (пакеты,
systemd-служба и .app названы так же; переименование — отдельная задача).

## Файл sirius.ini

Если рядом с exe лежит `sirius.ini` (пример — `res/sirius.ini.example`), его
значения заменяют зашитые в сборку. Удобно, чтобы сменить сервер без пересборки
или собрать «пустую» сборку и раздавать ini. Нужен как минимум `id_server`.

Файл читается из папки самой программы: для установленной версии это
`C:\Program Files\SRSDesk\sirius.ini` (подхватится после перезапуска службы).
Переносной exe распаковывается во временную папку, поэтому ini рядом с ним
не увидит — используйте установку или зашитые секреты.

## Как это работает у клиента

* **Новая установка** — при первом запуске сервис сам прописывает сервер Сириус,
  вводить ничего не нужно.
* **Режим «Сервер Сириус»** — при каждом запуске службы параметры сверяются со
  сборкой/ini, так что новая сборка с другим адресом или ключом сама обновит
  клиентов. В режиме «Свои настройки» ничего не перезаписывается.
* **Уже настроен свой (корпоративный) сервер** — настройки не трогаются.
* **Настройки → Сеть → ID/Ретранслятор** — выпадающий список:
  * *Сервер Сириус* — параметры из сборки, поля скрыты;
  * *Свои настройки* — можно ввести корпоративный сервер или оставить поля
    пустыми, тогда используются общедоступные серверы RustDesk.
* Проверка обновлений с rustdesk.com отключена, чтобы официальный релиз не
  заменил брендированную сборку.

## Брендинг

* Цвета: `MyTheme.siriusBlue` / `MyTheme.siriusBlueLight` в `flutter/lib/common.dart`.
* Логотипы и иконки: `res/` (исходники), `flutter/assets/icon.svg`,
  `flutter/windows/runner/resources/app_icon.ico`, иконки Android/iOS сгенерированы
  из `res/icon.png`.
* Иконка macOS (`flutter/macos/Runner/AppIcon.icns`) пока прежняя.

## Известные ограничения

* Переносной (не установленный) режим на Windows ищет свой вспомогательный
  процесс по имени `srsdesk.exe`, а распакованный файл называется `rustdesk.exe`.
  Проверка на уже запущенный процесс в этом режиме не срабатывает; после
  установки всё штатно.

## Обновление из апстрима

```sh
git remote add upstream https://github.com/rustdesk/rustdesk.git  # один раз
git fetch upstream master
git merge upstream/master
git submodule update --init --recursive
```
